# S01: Accurate quotes and auditable credit charges

<!-- visibible-modernization:S01 -->

## Problem Statement

Guests cannot rely on displayed costs when catalog units, fallback prices, reservation rules, and final charge records disagree. Operators cannot reliably compare provider spend with revenue.

## Solution

Give each accepted operation a versioned quote, a visible maximum charge, and a receipt. Calculate money consistently and reconcile credits exactly once.

## User Stories

1. As a guest, I want to see an estimate and maximum charge before paid work, so that I understand what I authorize.
2. As a guest, I want to receive unused reserved credits automatically, so that failed or cheaper work does not lock my balance.
3. As a guest, I want to pay at most the accepted maximum, so that a provider price change cannot create an unexpected debit.
4. As a guest, I want to use supported resolution settings at an explainable price, so that I pay for the output I selected.
5. As an operator, I want to see planner and image provider spend separately, so that I can measure the full cost of a generation.
6. As an operator, I want to distinguish zero usage cost from missing data, so that I do not manufacture charges from unavailable telemetry.
7. As an operator, I want to retry receipt delivery safely, so that reporting does not duplicate charges or costs.
8. As a maintainer, I want to test catalog fixtures in their original units, so that unit conversion errors cannot survive mocked examples.
9. As a guest, I want to use the documented small-balance allowance for explicit image generation, so that my remaining credits remain useful.

## Implementation Decisions

- Preserve one credit = USD 0.01 and 25% markup. Use decimal or checked fixed-point monetary arithmetic; round credits once at the final operation total, with a one-credit minimum for successful chargeable work. Reject nonfinite and negative input; represent known zero, estimated, and missing usage distinctly.
- Normalize provider pricing to explicit billable units in a catalog adapter. Emergency values have identical units and provenance. A price field name alone is not proof of a flat per-image cost. Unsupported/unpriceable paid choices fail closed with a user explanation; browsing remains free.
- Quotes contain immutable input fingerprint, catalog and policy versions, estimate, maximum charge, creation time and 5-minute expiry. Accepted quotes freeze the customer policy for that operation. A stale quote requires refreshed acceptance before provider work.
- For new execution, charge successful work from reported usage plus markup, capped at the accepted maximum. Missing usage uses the accepted estimate, capped likewise, and remains labeled estimated. Never retroactively increase a finalized guest charge or reprice historical ledger entries. Keep provider corrections as separately versioned accounting records.
- For quote admission preserve the 100-credit chat ceiling and existing non-admin daily limit default, but track provider-spend exposure separately from customer billings. Bound chat input and output; reserve exposure for concurrent admitted work. Reconcile daily exposure by reservation day, including midnight crossings.
- Replace the 35x rule with explicit max-charge holds. Preserve the five-credit spend-down allowance for explicit image requests: positive balance, estimate no more than five credits above it, maximum charge and hold capped at that balance, remainder absorbed by Visibible. Auto-generation requires full estimated affordability. New UI states show the estimate and any higher maximum distinctly.
- Image failure, cancellation before durable completion, and unusable final output release the customer reservation; record all known provider spend. A completed, durably saved image remains chargeable even if its HTTP delivery is interrupted. Successful chat means accepted nonempty output with a permitted finish outcome; error/cancelled streams release under S04.
- Write wallet changes, immutable settlement receipt, and delivery intent in one Convex transaction. The Neutral Cost component is a reporting projection, not a second wallet. Projection processing must have atomic operation-key deduplication and recoverable retries.
- Learn estimates only from actual provider usage. Use the existing nearest-rank 75th percentile over settings-normalized buckets, at least five recent actual samples for a learned quote, a 30-day freshness window, and at most the latest 30 samples. Less-specific estimates are visibly lower confidence and never authorization ceilings. Backfill is an explicit bounded operator operation.
- Keep pure quote arithmetic in a shared library. Both legacy fixes and new operations call it; typed adapters separate raw usage and billable amounts.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Test quote-to-reservation-to-settlement through the wallet interface with real Convex handlers and realistic provider fixtures.
- Cover one-credit rounding, free usage, absent usage, fallback unit parity, concurrent holds, duplicate finalization, capped shortfall and midnight release.
- Crash after settlement but before reporting; replay delivery concurrently and assert one wallet effect and one projection.
- Extend existing credit-flow and session invariant tests; do not reproduce the arithmetic in mocks.

## Out of Scope

- New credit bundles or markup changes
- Repricing old guest charges
- Automated refunds to an external Lightning wallet
