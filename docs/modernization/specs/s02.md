# S02: Verified guest access and protected credit ownership

<!-- visibible-modernization:S02 -->

## Problem Statement

Private operations use inconsistent ownership checks, and session expiry is mixed with retention of purchased credits.

## Solution

Keep anonymous browsing while making private reads and writes use verified identity. Preserve credit ownership independently of expired access credentials.

## User Stories

1. As a guest, I want to browse without registering, so that I can read Scripture immediately.
2. As a guest, I want to see only my private balance and invoices, so that my spending history stays private.
3. As a guest, I want to see the same balance in two tabs, so that I can understand concurrent purchases and generation.
4. As a guest, I want to receive clear information about cookie loss and expiry, so that I know the limits of anonymous access.
5. As an operator, I want to retain funded session records after access expires, so that cleanup cannot erase credit ownership.
6. As an operator, I want to revoke compromised guest or admin access, so that private operations stop promptly.
7. As a maintainer, I want to derive ownership from verified identity, so that a supplied session ID is never sufficient authorization.
8. As an existing guest, I want to keep my current credit balance through migration, so that authentication changes do not make me pay again.

## Implementation Decisions

- Use a Next.js token broker backed by the existing valid signed HttpOnly guest cookie and a Convex custom JWT integration. Issue short-lived RS256 tokens with kid, subject, issuer, audience, issued-at and expiry; keep the signing key server-side and publish only verification keys. Choose a 5-minute token lifetime and test rotation overlap.
- Convex derives the guest subject from verified identity and resolves the existing SID mapping. Do not pass or accept an arbitrary owner SID as proof. Privileged tier comes from the current database record, not a stale client token.
- First close unauthenticated access to private session, invoice, credit-history and bulk functions. Keep intentionally public library reads public. Server-to-server callers use a separate authenticated interface while transitioning.
- Preserve existing seven-day idle and thirty-day absolute HTTP access expiry for this program. Expiry ends access, not ownership; this program adds no cross-device or lost-cookie recovery and must say so before purchase. Token refresh cannot extend the underlying session beyond its allowed expiry.
- Never automatically delete a positive balance, unresolved reservation, invoice needing reconciliation or associated financial record. Preserve expired funded sessions as inaccessible records pending a separately specified recovery feature. Never accept an expired cookie as proof solely to restore funds.
- Migrate a valid existing session to verified Convex identity without a credit transfer. Existing immutable ledger/SID relationships remain resolvable. Query balances reactively and remove client-side arithmetic.
- Guest token issuance follows same-origin/CSRF rules and bounded rate limits. Tokens stay in memory, not localStorage. A revocation or deleted subject causes private functions to reject even a cryptographically valid token.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Use two guest identities and an unauthenticated client against actual private handlers; known foreign IDs must not grant access.
- Test cookie/token expiry, bad issuer/audience/signature, signing-key rotation, revocation and downgraded admin access.
- Verify purchases, holds, releases and charges in two browser tabs without polling balance.
- Retain prior session/IP tests while adding authenticated query behavior.

## Out of Scope

- Named accounts
- Cross-device balances or recovery codes
- Changing anonymous session expiry durations
