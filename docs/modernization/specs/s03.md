# S03: Lightning purchases that settle without an open tab

<!-- visibible-modernization:S03 -->

## Problem Statement

A guest can pay within the invoice window but receive no credits if the app observes the payment after local expiry. Browser polling is also responsible for settlement progress.

## Solution

Create recoverable invoice attempts and reconcile LND truth on the server. Grant each purchased credit bundle once, even after the guest leaves.

## User Stories

1. As a guest, I want to pay the existing USD 1 or USD 3 bundle, so that I can buy credits using Lightning.
2. As a guest, I want to leave the payment screen after paying, so that I still receive my credits.
3. As a guest, I want to see paid status when a payment is first observed late, so that a local timer cannot discard payment truth.
4. As a guest, I want to retry invoice creation after a connection problem, so that I do not get unrelated duplicate payment requests.
5. As an operator, I want to find incomplete invoice creation attempts, so that I can recover partial failures.
6. As an operator, I want to reconcile old pending or locally expired invoices, so that previously missed payments are detectable.
7. As an operator, I want to confirm a payment repeatedly without extra credits, so that retries are safe.
8. As a guest, I want to see a delayed-check state during an LND outage, so that I do not mistake unavailable status for payment failure.

## Implementation Decisions

- LND verified settlement is authoritative. Validate payment hash, amount and settled state; a locally elapsed invoice deadline prevents presenting it as payable but cannot override a settled payment. Separate local display expiry from reconciled provider state.
- Use one atomic confirmation mutation for the invoice-paid record and purchase ledger entry, uniquely keyed by payment hash/invoice identity. Repeated confirmation returns the existing result without another credit.
- Record an invoice-creation intent before external I/O and reconcile any ambiguous creation result. Prefer a provider-supported stable payment identity; validate the deployed LND capability first. If safe lookup is unavailable, expose an unresolved creation attempt rather than silently generating another payable invoice.
- Use bounded Convex scheduled reconciliation with an authenticated LND adapter. Validate network reachability from the chosen execution environment before moving credentials. If direct access is unavailable, use a narrowly scoped authenticated server bridge; never require the browser to drive settlement.
- Poll new pending invoices at most every 15 seconds, back off on failures up to 5 minutes, and reconcile late-observed states until LND establishes terminal truth. Run a bounded historical sweep for locally expired/unresolved records. Expose retry age and operator action instead of an infinite invisible loop.
- Freeze sats amount, USD bundle and credit count at invoice creation. Keep the existing bundle prices and invoice-only credentials. Observe invoice status through authorized reactive queries once identity integration is available.
- Preserve financial evidence and hashed identifiers; never expose macaroons or payment preimages in logs, public responses, specs or tickets.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Test timely payment first observed after local expiry through both HTTP confirmation and real Convex settlement.
- Simulate crash before and after LND creation, delayed settlement, outage, duplicate notification, amount mismatch and concurrent confirmations.
- Leave/close the browser, settle a fake invoice, reopen and assert one credit addition.
- Use existing invoice IP-binding tests as prior art; add actual invoice handler tests instead of only mocked credits.

## Out of Scope

- Fiat checkout
- New bundles
- External wallet refunds
