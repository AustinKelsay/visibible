# S05: Durable single-verse image generation

<!-- visibible-modernization:S05 -->

## Problem Statement

An HTTP retry can duplicate provider work and charges. A generation may be marked succeeded before its image is saved, and request failure can strand its progress.

## Solution

Accept one authenticated generation intent, run it durably, persist its image and settle once. Readers can recover the result by generation identity.

## User Stories

1. As a guest, I want to generate an image for a selected verse, so that I can visualize what I am reading.
2. As a guest, I want to retry the same request safely, so that a lost response cannot make me pay twice.
3. As a guest, I want to return after a disconnection, so that I can recover the saved image and receipt.
4. As a guest, I want to see useful progress states, so that I know whether work is queued, generating or saving.
5. As a guest, I want to cancel work that has not completed, so that I can control spending and wait time.
6. As an operator, I want to inspect each provider attempt, so that unknown outcomes are recoverable.
7. As a guest, I want to know whether an image is saved, so that temporary output is not presented as durable.
8. As an operator, I want to recover a storage failure without regeneration, so that recovery does not create another paid provider request.

## Implementation Decisions

- Use a mutation to atomically accept owner-scoped operation identity, canonical input fingerprint, quote and reservation, then schedule a Convex Workflow. Keep one workflow per generation and store large bytes outside workflow journals; pass IDs between steps.
- Transport retries reuse the same owner and intent ID. A deliberate new variation uses a new ID. Reuse with a different fingerprint is a conflict. Historical and archived operation identities retain deduplication tombstones.
- Operation states are accepted, planning, generating, saving, succeeded, failed, cancelled and uncertain. Only valid transitions are permitted. Terminal outcomes are immutable; uncertain is a recovery state, not a license to repeat paid work.
- Persist provider-attempt identity before calling the provider; record result identity and usage as soon as available. Use provider idempotency only when its behavior is verified. Disable automatic retries of non-idempotent paid steps; ambiguous completion enters uncertain and releases the customer hold after a maximum 30-minute resolution window, retaining operator reconciliation and provider cost evidence.
- Save validated output, then atomically finalize the saved-image link, receipt and charge. Store provider spend independently of delivery. Storage retry uses existing output and never silently invokes the model again.
- Cancellation stops pending steps. If durable success committed first, cancellation returns that success and its charge; otherwise cancel/release according to the policy. Provider cancellation is best-effort and any spend remains accounted for.
- Initially support the current default image model through the existing provider transport. Extend other supported models through the adapter contract; adopting a dedicated image API requires verified capability and fixture parity, not a simultaneous provider migration.
- Legacy route fixes for request deduplication and terminal-state guards land independently before switching execution. A per-operation executor version ensures that legacy and new implementations cannot both perform one generation.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Test the generation request/status/result interface with real database handlers and fake provider/storage effects.
- Inject failures after admission, provider success, storage and settlement; assert one debit, one image record and a recoverable result.
- Test duplicate intents, fingerprint conflicts, foreign owners and cancelled/terminal races.
- Run a preview resume-after-disconnect exercise before enabling the new executor.

## Out of Scope

- New artistic styles
- Automatic provider failover after an ambiguous paid request
- Exactly-once guarantees for an external service without supporting evidence
