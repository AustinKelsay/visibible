# S06: Bulk generation managed by the server

<!-- visibible-modernization:S06 -->

## Problem Statement

Bulk jobs depend on browser locks and heartbeat timers. Interrupted generating items and client-written counters can leave progress inaccurate.

## Solution

Let guests request a verse scope and observe a server-owned queue that continues without an open tab.

## User Stories

1. As a guest, I want to generate next verses, chapter ranges or a book, so that I can illustrate a meaningful scope.
2. As a guest, I want to close the tab while a job runs, so that my accepted job continues.
3. As a guest, I want to pause and resume a job, so that I control future work.
4. As a guest, I want to cancel a job, so that remaining verses do not start.
5. As a guest, I want to see accurate progress in two tabs, so that both views describe the same job.
6. As a guest, I want to resume after buying credits, so that completed items are not repeated.
7. As an operator, I want to limit concurrent provider work, so that a large scope cannot exhaust capacity.
8. As a guest, I want to recover interrupted work, so that one abandoned item cannot block the whole job.

## Implementation Decisions

- Bulk items invoke the same generation interface as single images with a stable intent ID derived from job and item. Preserve existing scope semantics, reference order and per-item charging.
- Create a job through verified identity. The browser can start, pause, resume or cancel, but only server workers write outcomes and aggregate credits. Update item state and parent counters transactionally from idempotent item transitions.
- Begin with one active item per guest/job and two active provider calls globally in the new execution pool. Make limits configurable and enforce them server-side. Keep paid request quotas and admin rate limits; job scheduling is not an exemption.
- Queue creation is a resumable building phase with bounded insertion batches in separate transactions. Execution begins only when the intended queue is complete. Bound to one canonical book per job and one active/paused job per guest, preserving the existing product scope.
- Pause prevents new claims while allowing the current item to finish. Cancel prevents future claims; an already running item completes under the single-generation cancellation contract. Bulk cancellation must display in-flight work clearly.
- Insufficient credits pauses for explicit guest resume. Provider throttling records retry-after and pauses with an actionable status; resuming before retry-after does not start work. Retry only safely retryable infrastructure steps.
- Recover abandoned claims by inspecting the linked generation outcome, not simply moving every generating row back to queued. Resolve succeeded items and uncertain attempts without duplicate provider calls.
- Remove browser leases, heartbeat timers and arithmetic only after the server path passes failure recovery and two-tab tests. Keep a compact reactive progress view with completed, failed, skipped and pending counts.
- At job acceptance record per-item maximum charges and an aggregate authorization ceiling; no upfront whole-job debit. Requote and pause for explicit acceptance when a later item exceeds either ceiling. Existing accepted items retain their own quote and policy version.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Exercise start-to-completion with fake provider effects and actual job/item mutations.
- Test closing all tabs, two tabs, server interruption, insufficient credits, throttling, pause/cancel races and resume.
- Create the largest canonical book scope and verify bounded transaction sizes and resumable insertion.
- Assert counters equal item outcomes and each item has at most one settled generation.

## Out of Scope

- Parallel per-guest generation beyond configured limits
- New scope types
- Upfront charging for an entire book
