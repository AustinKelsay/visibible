# S09: Consistent reader controls and preferences

<!-- visibible-modernization:S09 -->

## Problem Statement

Generation controls depend on a mounted image renderer. Preferences and balances have multiple local copies, and onboarding/purchase states are tightly coupled.

## Solution

Let reader, gallery and header share one generation interface. Preserve navigation while reducing local synchronization and splitting unrelated UI state.

## User Stories

1. As a reader, I want to generate from the reader or gallery controls, so that changing view does not disable the command unexpectedly.
2. As a reader, I want to navigate while images load, so that passive loading does not look like paid generation.
3. As a reader, I want to use keyboard and mobile gestures, so that navigation remains accessible.
4. As a reader, I want to keep my selected translation and model, so that refresh does not reset my choices.
5. As a reader, I want to open a specific saved image, so that history loading does not choose another image.
6. As a guest, I want to see accurate generation progress and balance, so that I do not act on stale local data.
7. As a new reader, I want to choose free browsing from welcome, so that payment onboarding does not obstruct reading.
8. As a guest, I want to buy credits without confusing admin or welcome states, so that purchase steps remain understandable.

## Implementation Decisions

- A verse generation module owns request/status/quote commands independently of HeroImage. Reader, gallery and header use it directly. Keep React local state for visual concerns: selected image, loading, gestures and fullscreen.
- URL defines verse location, gallery base view and requested image. Preserve existing supported in-memory view overrides where tests demonstrate the intended behavior. Model/translation cookies are authoritative for server-visible preferences; localStorage supplies boot hints and stores purely client ratio/resolution preferences. Version/migrate preferences without changing user choices.
- Use Convex subscriptions for saved history, generation state and authorized balance. Remove cache-busting tokens only once normal subscriptions and selected-image lookup cover recovery.
- Separate welcome, bundle selection, invoice lifecycle and admin access into small UI modules within the existing design. Consolidate welcome flags with a migration that respects either prior completion flag. Keep Browse for Free and existing welcome behavior; redesigning when to show it is excluded.
- Preserve mobile/keyboard behavior, fullscreen exit order, focus handling, gallery image links, loading distinctions and layout. Use browser verification and screenshots for visible changes.
- Remove duplicate local cost/balance arithmetic. Present estimate, maximum, reserved amount and final charge using values from the owning modules. Make unsupported saved model settings visible and recover to a validated choice.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Browser tests follow reader -> gallery -> selected image -> generate -> saved result across refresh.
- Exercise keyboard, touch, Escape, focus restoration, narrow/wide layouts and loading/error states.
- Use two tabs to verify preference/balance expectations; inspect visible values rather than implementation hooks.
- Replace existing string/source checks with behavioral tests only for their meaningful contracts.

## Out of Scope

- Visual rebranding
- New navigation patterns
- New onboarding sales flow
