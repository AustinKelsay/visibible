# S10: Evidence-based model and prompt releases

<!-- visibible-modernization:S10 -->

## Problem Statement

Model age does not establish quality, and current tests do not measure Scripture grounding or image usefulness. The stated chat release evaluation process lacks a committed dataset and repeatable runner.

## Solution

Create repeatable evaluations and compare current models/prompts with candidates before changing defaults or removing the planner.

## User Stories

1. As a reader, I want to receive grounded explanations, so that chat does not invent references or overstate interpretation.
2. As a reader, I want to see images suited to different Scripture genres, so that symbolic or difficult passages receive useful treatment.
3. As an operator, I want to compare actual cost and latency with quality, so that default choices are informed by evidence.
4. As a maintainer, I want to rerun the same cases after a provider change, so that regressions are comparable.
5. As a reviewer, I want to see failed and borderline cases, so that average scores do not hide serious failures.
6. As an operator, I want to restore a prior model configuration, so that a regression can be reversed promptly.
7. As a guest, I want to retain a functioning default if a candidate disappoints, so that modernization does not force a worse model.
8. As an operator, I want to compare direct and planner-assisted images, so that the extra planner call must justify its cost.

## Implementation Decisions

- Commit at least 30 chat cases covering single verses, adjacent context, contested interpretations, off-topic requests, prompt injection and harm-sensitive questions. Each case includes exact context, expected behavior notes and rubric. Use the existing four 0-2 dimensions and release thresholds.
- Commit at least 24 image cases spanning narrative, poetry, prophecy, genealogy, symbolic and difficult passages. Score passage relevance, visual clarity, unwanted text/artifacts and style adherence. Record prompt, model, settings, seed when supported, image IDs and human review notes.
- Run baseline and candidates against identical inputs. Keep judge model/configuration versioned and supplement automation with human review of failures/edge cases; model-graded output alone is not approval.
- Capture actual provider spend including planner, completion/failure rate, latency distribution and estimate variance. Use at least three repeated image runs per case for planner comparison where budget permits; otherwise label the result inconclusive rather than inventing confidence.
- Planning creates the evaluation work, not authorization for unbounded provider spend. Provide dry-run and a configurable hard evaluation budget. Implementation may run local fake-provider checks; live runs require available budget authority and credentials, with a human owner recorded before production model release.
- Candidate default changes are conditional on evidence. A completed comparison with a documented no-change result satisfies the evaluation ticket. Provider API adoption likewise requires model/capability compatibility; catalog presence alone is insufficient.
- For approved releases record baseline/candidate scores, risk, exact rollback configuration and first-24-hour monitoring owner. Preserve the existing manual chat release gate.

## Testing Decisions

Tests assert externally observable behavior through the highest practical existing interface. Exercise actual application handlers and replace external paid/network effects with controlled adapters. Avoid tests that repeat implementation arithmetic or only inspect source text.

- Test the runner with deterministic fake providers: complete/failing outputs, missing cost, timeouts and budget exhaustion.
- Verify report reproducibility metadata and failure visibility.
- Keep mechanics and theological/visual quality checks distinct.
- Smoke-test rollback configuration without generating duplicate paid production work.

## Out of Scope

- Changing defaults without evidence
- Training models
- Automated theological authority or unsupervised evaluation sign-off
