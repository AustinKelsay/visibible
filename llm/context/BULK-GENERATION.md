# Bulk image generation

[BulkGeneratePanel](../../src/components/bulk-generate-panel.tsx) builds a queue and estimate using [bulk-generation.ts](../../src/lib/bulk-generation.ts). Scopes are next verses, chapter ranges, or an entire book. Next verses exclude the current verse. Chapter scope starts with the current chapter only at verse 1; otherwise it starts with the next chapter. Book scope includes the whole book.

[BulkGenerationProvider](../../src/context/bulk-generation-context.tsx) runs sequential browser requests to `/api/generate-image`. [convex/bulkGenerations.ts](../../convex/bulkGenerations.ts) persists job settings, queue rows and progress so a session can recover its active/paused job. Closing the browser does not leave a server worker running the remaining queue.

- Every generated verse uses the normal image route's validation and charging; the total estimate is not an upfront bulk charge.
- Insufficient credits pause the job and return the current item to the queue. HTTP 429 pauses it with a blocked UI state for manual resume. Resume retries the item under its stable per-item request ID. Other failed requests are recorded as failed items.
- Pause/cancel controls stop subsequent work; they do not abort an already-sent image request.
- **Engine and style binding (#178).** A job records its art style at creation (`artStyleId`, Classical until the reader can choose) and binds to the engine its first accepted item ran on (`engine`, set through `bindEngine` from the route's response). Every item is submitted with `style` and, once bound, `engine`; the route refuses with 409 "Engine binding changed" rather than admitting the item on another engine, and the coordinator then pauses the job with `pausedReason: engine_unavailable` and keeps its configuration and completed outcomes. A retryable 503 (a scene still preparing, a style temporarily unavailable) is retried three times and then pauses the job the same way (`preparing` or `style_unavailable`); 402 and 429 pause it with `credits` and `rate_limited`. Resume clears the reason and retries under the same item request id.
- **Recovery.** Items are submitted under the stable id `bulk-<jobId>-<order>`, so a resubmission is a replay. When a browser disappears mid-item, the next coordinator calls `reconcileInterrupted` before submitting anything: it settles items left "generating" from their request records (a succeeded request completes the item with its charged credits, a failed one fails it, an accepted-but-unfinished or never-admitted one goes back to the queue). A 202 from the route (an earlier attempt still running) is waited on, not repeated.
- **Release checks.** `countItems` (server secret) reports, per engine, how many queued or generating items were never admitted (unstarted) versus accepted and not yet ended; an accepted paid attempt is never counted as unstarted. `bindLegacyJobs` (server secret, idempotent) binds every job without an engine to legacy and Classical before public activation: `npx convex run bulkGenerations:bindLegacyJobs '{"serverSecret":"…"}'` against the deployment, once, before switching `GENERIC_ENGINE_MODE`.
- Job and verse reads and controls require the verified Convex guest identity: its subject must match the supplied session ID, and the job must belong to that session. Unauthorized reads return no job; writes are rejected. These functions do not take the server secret, so the owning guest can still write item outcomes while the browser runs the queue. See [Security](SECURITY.md) for the distinction from paid generation authorization.
