# Preferences

[PreferencesProvider](../../src/context/preferences-context.tsx) stores translation, image model, chat model, image aspect ratio, resolution, art style (`artStyle`, default `classical`) and automatic generation (`autoGenerate`) in `visibible-preferences` localStorage. `autoGenerate` is on only when the stored value is exactly `true`: a guest is charged for an automatic image without seeing its price, so nothing but their own choice in the image settings turns it on. Defaults come from the Bible and model libraries; validation and hydration behavior live in the provider.

Every save writes the image model along with `defaultImageModel`, the default at save time. Since [ADR 0012](../../docs/adr/0012-one-image-call-from-the-text.md) generation runs on one model whatever is saved, so on load the saved image model is always replaced by the current default, and its resolution normalizes to what that model supports. A model picked during a visit lasts only for that visit. While the catalog offers one usable model, the header menu and the generate modal name it (with its price) instead of offering a choice, and the settings popover leaves the model section out ([soleImageModel](../../src/lib/image-models.ts)).

Translation, image model and chat model setters also write cookies. Translation and image model changes refresh the route. Ratio and resolution changes apply to subsequent generation; chat model changes apply to subsequent messages. Selecting a model does not itself guarantee generation or catalog availability.

Model defaults, ratio/resolution options and resolution normalization are defined in [image-models.ts](../../src/lib/image-models.ts) and [chat-models.ts](../../src/lib/chat-models.ts); the per-model supported-resolution registry lives in [image-catalog.ts](../../src/lib/image-catalog.ts). Models without resolution support use the normalized 1K estimate bucket.

Reader/gallery/video state is separate from saved preferences; see [Navigation](NAVIGATION.md). Preference events use the source values defined in [analytics.ts](../../src/lib/analytics.ts).

The art style ([art-styles.ts](../../src/lib/art-styles.ts)) is selected beside the model in the header and in the generate modal: Classical, Ink & Watercolor, Fresco, Storybook and Byzantine Icon in the style library's order, with the shared labels and descriptions. Readers can generate the first four; Byzantine Icon is owner-only and shows as temporarily unavailable to everyone else ([admission](../../src/lib/engine/admission.ts)). A saved id the library does not know is left in storage and the default is used; a saved style the server is not admitting right now (rollback) stays selected and is reported unavailable rather than swapped for Classical. Changing the style does not refresh the route: generation, verse history, chapter gallery, book and chapter markers, variation counts and auto-generation follow it reactively through the style-aware library queries ([Image persistence](IMAGE-PERSISTENCE.md#art-style-at-read-time)), and bulk jobs record it at creation.
