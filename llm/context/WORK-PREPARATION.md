# Work briefs and shared art styles

[Work preparation contracts](../../src/lib/work-preparation.ts) validate the repo inputs for the generic image engine. Reading, storage, canon and reference preparation feed the generic request path described in [the accepted engine specification](https://github.com/AustinKelsay/visibible/issues/165). Admission remains controlled by `GENERIC_ENGINE_MODE`; the legacy path and its prompts were removed (#184). Structural validation passing is not production release approval; see [the release workflow](../workflow/ENGINE_RELEASE.md).

## Shared style library

The registered files are [Classical](../../styles/classical.json), [Ink & Watercolor](../../styles/watercolor.json) and [Byzantine Icon](../../styles/icon.json). Their canonical IDs are `classical`, `watercolor` and `icon`. `classical` preserves the existing default ID; the new label is `Classical`. The experimental `watercolour` ID is not an alias.

Each style has exactly `id`, `label`, a one-line `description`, and six required rendering parts: `rendering`, `palette`, `lighting`, `materials`, `composition`, `negatives`. `createStyleLibrary(unknown)` rejects missing/blank parts, invalid or duplicate IDs and extra fields. `SHARED_STYLES` is the registered library. A new style requires an explicit file/import/registration change; a generated brief cannot invent one.

`formatStylePrompt(style)` emits only the six parts. Labels and descriptions help the drafter and picker select styles; descriptions never enter image prompts. Style files contain rendering choices only. Biblical-era wording and reverent tone belong in the Bible's brief/eras, and whether a figure gets a halo belongs in depiction rules. The new Classical file retains the artwork, fresco and manuscript negatives; Watercolor includes the stronger prohibition on paper margins, unpainted corners and blank paper backdrops. Existing production prompt strings are unchanged until integration.

`inspectStyleScope(style, terms)` flags known work, person, place and era names in the six prompt parts, returning the offending field and term. Supply names and aliases from the imported work, era definitions and reading-pass identities for every supported work when reviewing a shared style. Matching ignores case and punctuation and respects phrase boundaries. A style's historical technique name, such as Byzantine Icon, is not itself a content-era instruction: review any matching flags in context.

This is a deterministic lexical check, not a semantic classifier. It cannot discover names omitted from the supplied vocabulary or detect every indirect work-specific assumption. Human review of the complete rendering text remains part of the style-file PR.

## Brief file contract

An eventual `works/<work-id>/brief.json` contains:

```text
schemaVersion: 1
workId
tone
depictionRules: [{ text, styleIds?: [registered IDs] }]
eras: [{ id, label, people, dress, buildingsAndObjects, technology }]
styleIds: [ordered registered IDs; first is default]
```

`validateWorkBrief(unknown, library?)` validates the whole file. IDs are lowercase slugs, era IDs are unique, and the nonempty offered-style list has no duplicates. A depiction rule can name registered style IDs in its optional `styleIds` condition, even if a particular work does not currently offer them. Conditions are preserved explicitly; they do not become unconditional instructions. An absent condition applies across styles. Empty or unknown conditions fail.

The brief is a short page, with a hard ceiling of **400 whitespace-delimited words** across tone, rule text, era labels and era descriptions. IDs are not counted as prose. There is no minimum word count: a simple work can use a shorter brief. Every era must specify people, dress, buildings/objects and technology.

`formatBriefPrompt(brief, eraId)` returns the tone, all depiction rules (including their style conditions) and that era's fields. Validation checks the exact formatted string for **every era**, including labels, punctuation and line breaks, against the **1,200-character** limit (`String.length`, UTF-16 code units). Unknown eras fail. Nothing is truncated or silently normalized. A long later era is rejected even if the first era fits. The full style-neutral form retains conditions for the later planner/rendering stages to interpret under the accepted precedence.

Section-to-era assignments are analysis output and are rejected as extra fields in the brief. `selectMainEra(brief, sectionEraIds)` counts those assignments and selects the era with the most sections. Ties use brief order; empty assignments and unknown era IDs fail. It does not guess a main era before sections exist.

## Draft scope review and canon hints

`reviewDraftBrief(draft, entries, sectionReferences?, library?)` accepts single-entry IDs, kinds and names/aliases from the reading pass. It validates the draft, then proposes a cleaned brief by routing depiction-rule text that names an entry into `canonHints`. Each hint retains the original rule, condition, entry ID/kind and source path. The input is never mutated.

Named details inside required tone/era fields produce canon hints and `scopeIssues` with destination `canon`; those fields need rewriting, so the returned `brief` is `null`. Supplied chapter/episode references likewise produce issues directed to `section-look`. The helper does not silently delete required prose or invent replacement wording. Style IDs in structured conditions are not mistaken for character names.

These are conservative review suggestions. A real work-wide depiction policy may deliberately name a figure; the owner can retain such a policy in the brief PR. Structural validation accepts that choice, including registered style conditions. The draft reviewer is not an approval mechanism and its hints are not automatically published canon. Missing aliases and indirect descriptions still need reading-pass and owner review.

## Preference, precedence and content floor

`resolveWorkStyle(brief, savedPreference, availableStyleIds?, library?)` returns a registered style and the original saved preference. An offered preference is selected; an absent/unoffered preference uses the first offered style without overwriting the saved value. This preserves a visitor's preference when moving between works. If the selected style is temporarily unavailable, the helper returns `available: false` and keeps that selection; it does not choose a different style. Callers must enforce availability before generation. Persistence and reader UI are not implemented here.

`PROMPT_PRECEDENCE` is strongest to weakest: engine rules, brief content/depiction, style rendering, section look, scene plan. Briefs control what may be shown and the world's people/technology; styles control rendering. Thus an Icon gold sky can override literal section lighting without changing the scene's era or granting permission for halos.

`COMMON_CONTENT_FLOOR` belongs to the engine for every work: sexually explicit content and lingering gore are prohibited; serious battles, blood, death, crucifixion and non-sexual nudity are permitted. Provider filters may still refuse an otherwise permitted image. Strict brief/style schemas accept no field that replaces this floor, and engine rules outrank all prose. These validators cannot prove that arbitrary prose is semantically consistent with the floor; owner review and the later prompt assembler must preserve that precedence.

## Approval and changes

The [Bible and Holmes fixtures](../../tests/fixtures/work-briefs/README.md) are examples, not approved production inputs. No production brief is committed by this slice, and there is no `approved` boolean that can self-authorize one.

The later reading pass proposes a brief and an ordered set of existing styles with reasons. It writes a draft into the working tree for a **separate one-file brief PR** at `works/<work-id>/brief.json`. The owner reviews tone, each depiction rule, eras and the style set; merging that PR is the approval. Later edits use the same path. Merging tests, fixtures or validator code does not approve a work brief. Storage/readiness integration must still verify complete, compatible analysis before generation; approval alone is insufficient.

Style files are owner-authored repo data reviewed through their own PR. Run the structural and scope checks against supported work vocabularies, review rendering/content separation, and judge a candidate through the planned owner-run contact-sheet tool using the actual engine prompt path. That visual tool and its explicit provider-spend budget arrive with engine evaluation; this slice makes no image/model calls and adds no automatic preparation. Later storage tickets attach content hashes and dependency invalidation to approved input changes; saved images retain their original versions.

## Reading pass

`npm run works:read -- <work-id>` runs the owner's reading pass ([run.ts](../../src/lib/reading-pass/run.ts)) over `works/<work-id>/work.json`: one Claude Haiku 5.5 call per root division (a Bible book or a Holmes story) with reasoning off and schema-constrained JSON, a merge of the divisions' casts, moments for prose works, and the draft brief. Results are staged as a **candidate analysis generation** in Convex ([Analysis storage](ANALYSIS-STORAGE.md)) with stage-less entries, so the candidate cannot activate until the canon slice drafts stages; readiness never follows from this command alone.

- **Validation and bounded retries.** Each division's sections must cover its units in order with no gaps, overlaps, inverted ranges or unknown ids. Invalid answers are re-asked with the problems listed; an empty answer is re-asked with a coarser section target. Three attempts per division, every attempt kept in the run state as evidence, and a division that still fails is reported before the merge rather than silently skipped.
- **Merge.** Each shared name form or `same_person_as` link supplies a candidate group. Groups may overlap; only model-ruled identities connect them, so a chain of generic titles cannot create one enormous request. By default each request contains one group, with at most 150 member references. This avoids a union of per-group enums that the provider rejected as too large to compile; a single-group schema contains no union. Internal callers may explicitly batch groups within the member bound, but must account for the provider grammar limit. An individual alias with more than 150 members stops before paid merging and asks for refined aliases. Each group's provider schema enumerates only its own exact member keys, even when another group in the batch contains additional keys. Code still verifies every group and member exactly once; missing, duplicate or foreign keys retry at most three times with the rejected answer and problems supplied, then stop. If overlapping partial rulings both join and separate the same entries, the model reviews the full linked component in one bounded reconciliation request. Its complete partition supersedes only those partial identity decisions; it can split an earlier mistaken join. Original group decisions and paid answers remain audit evidence, and the final reconciliations are recorded separately. Components above 150 members or reconciliations still incomplete after three attempts stop before canon; complete initial and reconciliation responses are cached independently for recovery. There is no silent singleton fallback for an incomplete answer. Merged entries keep every alias, a one-line note and their division-local members as evidence for canon. Section casts are rewritten to merged ids with a `named` flag decided from the text.
- **Moments.** Bible units are their own moments. For prose, the model proposes runs of about 100–400 words inside each section; code checks tiling and splits runs over about 600 words at paragraph boundaries. Sections and moments are identified by their first unit.
- **Bible hints.** `works/bible-web/hints.json` (from `npm run works:bible-hints -- <pericopes.tsv> <TIPNR.txt>`) gives each book a target section count from Clear.Bible's pericopes and lists the name forms TIPNR attributes to several individuals in one book; the merge shows that count to the model as evidence. Neither dataset is read at image time, and no other work needs hints. Both are CC BY 4.0 and credited on `/about`.
- **Draft brief.** The model drafts tone, depiction rules, eras with section assignments and an ordered style set chosen from the registered library with a reason each; unknown style ids are dropped, never invented. The draft is converted to the brief contract, validated, and reviewed with `reviewDraftBrief` so single-entry rules become canon hints. `works/<work-id>/brief.draft.json` and its `brief.draft.review.json` sidecar (style reasons, canon hints, scope issues, validation and assignment problems) are written for the owner's one-file PR at `works/<work-id>/brief.json`; the draft files are not committed.
- **Budget, resume, dry run.** `--budget` sets a hard provider-spend ceiling checked from list prices before every call; `--dry-run` prints the plan and estimate without a call. State lives under `works/<work-id>/.preparation/<run>/state.json`, so a failed or repeated command resumes completed readings. Accepted merge batches are retained under `mergeResponses`, keyed by the initial model/prompt/schema identity, so even a repaired batch is reused after interruption. Every paid answer remains in `mergeAttempts` for audit; rejected attempts are never replayed. Incomplete reconciliations stop without discarding complete initial batches or other completed reconciliations; a resumed run only pays for the unfinished decisions. Owner spend is recorded per call in that state; guest credits are never reserved. A changed `work.json` needs a new `--run` name.

## Canon

`npm run works:canon -- <work-id> [--activate]` runs the canon step ([canon-run.ts](../../src/lib/reading-pass/canon-run.ts)) after the reading pass, against the approved brief at `works/<work-id>/brief.json` (its content hash is the brief version the generation is read against). Every entry that stands on stage or is a setting in at least one story section gets a canon entry; merely mentioned figures get none. One Haiku 5.5 call per entry, run a few at a time under the same budget and resumable state as the reading pass (`canon.json` beside the reading state), with the estimates of calls in flight reserved so parallel drafting cannot overshoot the budget.

- **Grounding.** The drafter gets the brief's tone, unconditional depiction rules and the eras the entry appears in, the owner-review hints that concern it, its aliases and note, the sections it is on stage in, and selected source units. The brief's unconditional depiction rules govern shared canon's rendered appearance. Rules with `styleIds` are excluded from the drafting request and retained in the brief for final rendering only; they must not change the shared `hasForm` flag or stage text for every style. Within the unconditional limits, text is binding, then the work's own illustrative tradition, then invention within the era; film and television adaptations and any real actor's or public figure's likeness are excluded by instruction.
- **Source context.** Selection alternates exact name/alias matches in the entry's member divisions with context from its on-stage sections (setting sections for locations). This supplies pronoun descriptions and variant names without language-specific alias rewriting. Within each pool, selection visits the ends then bisects the remaining intervals; the result is deduplicated and returned in reading order. The strict 14,000-character source limit counts complete formatted unit lines and separators. Units that do not fit are skipped whole, including an oversized single prose paragraph; smaller units can still fit. Long entries receive sampled evidence, not complete coverage. The prompt warns against treating omitted passages as absence or assigning another subject's appearance to the entry solely from shared section membership.
- **Conditional hints.** Entry-specific review hints with `styleIds` are also excluded from shared canon drafting and remain unchanged in the review artifact. The renderer reads depiction rules from the approved brief, not review hints; any such condition intended for rendering must be retained in that approved brief during owner review.
- **Stages.** Each stage is a complete description of about 500 characters: one frequent outfit, nothing relational or comparative, nothing situational. Characters and locations get up to three stages only where the text marks a change; objects one. Extra stages are dropped in code, over-long text is re-asked once, and every remaining problem is recorded. The drafter assigns each of the entry's sections to a stage; unknown stage ids fall back to the first stage.
- **Quotes.** Each stage cites the passages it relied on with unit ids. Code verifies every quote against the exact unit text (ignoring case, spacing and quote marks) and drops the ones that fail, recording `quote_check_failed` attention items when staging. Quotes stay in the stored entry for audit and are never sent in prompts.
- **No form.** When an unconditional depiction rule forbids a body or face, the drafter sets `has_form: false`. New no-form stages return `showing` instead of free-prose `text`: one to five selections from a closed vocabulary. Visual effects are light, radiance, cloud, mist and fire, with a literal colour (white, gold, silver, red, orange, yellow, green, blue, violet, black or multicoloured) and brightness (faint, soft, bright or brilliant); either quality can be unspecified. Wind, voice and unseen presence take no colour/brightness fields. Code compiles these positive selections into `Name: brilliant white radiance; fire.` rather than copying or rewriting a model paragraph. The schema rejects unknown values, extra prose fields and a stage representation inconsistent with `has_form`. Invalid responses use the existing maximum of two structural attempts; repeated invalid responses fail drafting without a prose fallback or new approval step. Entries with form keep their existing prose contract and anatomy/outfit fields.
- **No-form evidence and limits.** The model must still choose the correct form flag and effects permitted by the unconditional brief; vocabulary membership does not prove that a particular effect is allowed or grounded. The bounded representation deliberately cannot express arbitrary source comparisons, spatial arrangements or environmental effects. A needed effect outside this vocabulary requires a contract change, not free prose in an enum field or an invented replacement. Exact source imagery stays in supporting quotes; `appearance_from_text` may explain the constrained interpretation. Selected `showing` values stay in local canon state and are also retained on newly staged no-form entries, beside the unchanged compiled `text` and quotes. Scene preparation used to pass these effect names to the planner; since formless-effects v14 it passes no no-form canon at all ([Scene preparation](SCENE-PREPARATION.md#no-form-presences)). Historical prose stays valid without metadata; code never infers choices from it or backfills live records. Rendering receives complete stage text for entries with form; since generic-v11 a no-form entry's text stays out of image prompts ([ADR 0006](../../docs/adr/0006-unseen-presence-speakers-and-launch-bar.md)), and quotes remain outside image prompts. The imported source is unchanged. Sheets still skip entries by the stored `hasForm` flag. The [retained Daniel drafting failure](../releases/2026-10-22-daniel-context-candidate/README.md) and later [live v4 planning failure](../releases/2026-10-22-daniel-placement-v4/README.md) remain evidence of separate limits; the new input projection has no live v5 evaluation yet. No semantic checker, keyword scrubber or extra model call is added.
- **Draft version.** New drafts record `CANON_PROMPT_VERSION` (`2026-10-22-canon-showing-v3`) as `promptVersion` in their local canon state and as a `prompt:canon` input on staged entry records. Older state, including no-form prose drafts with an earlier version or no version, resumes unchanged. Updating the drafter does not invalidate saved canon; `--redraft id,id` is required to apply it to selected existing entries, with owner versions still carried forward on activation. Controlled-provider tests cover the new representation, retained source quotes, source selection and explicit-redraft behavior. A separate bounded live evaluation is still needed before drawing conclusions about generated canon or images.
- **Staging and activation.** The command stages the complete analysis (entries with stages, sections with final stage assignments, moments) as a new candidate generation and, with `--activate`, activates it; the store carries forward owner versions by id and lists unmatched ones for attention ([Analysis storage](ANALYSIS-STORAGE.md)). Required canon is what completes structural readiness; no per-entry approval exists. `--redraft id,id` redrafts named entries; owner versions are preserved by the store at activation, so a redraft never overwrites an owner edit. Nothing drafts canon on a reader's image request: the generation route has no path to these modules.

## Reference images

`npm run works:references -- <work-id>` runs the reference step ([references-run.ts](../../src/lib/engine/references-run.ts)) over a work's active analysis. It makes a Classical reference sheet for every entry present in two or more story sections, one per stage a cast uses, skipping entries with `hasForm: false`, and one style reference per style in the brief's set, Classical included ([ADR 0004](../../docs/adr/0004-forgiving-scene-preparation.md)). Both come from fixed templates ([references.ts](../../src/lib/engine/references.ts)) on Nano Banana 2 Lite: three views for characters and two for locations and objects on a plain grey background, with the entry's own eras (those of the sections it is in, never the main era as a fallback) and the likeness prohibition; one outdoor scene of the main era with nothing bearing writing for a style reference.

A cheap vision model (Claude Haiku 5.5) checks hard faults only: text, a border or frame, extra figures, a missing view or different subjects across views for sheets; people, writing, borders or margins for style references. At most three attempts, each fed the previous reasons. Likeness remarks become `canon_note` attention items, never retries. After three failures the reference is omitted, a `sheet_failed` or `style_reference_failed` attention item is opened, and moment images proceed without it; references are never readiness gates.

The style-reference check inspects the whole perimeter and every corner. A partial, irregular paper margin or fading wash fails even when most of the picture is painted; pale clouds or light objects inside a continuous scene do not alone constitute a margin. Failure reasons should name observed faults so retry feedback does not ask for changes to already absent people/text. The [retained-image calibration](../releases/2026-10-20-watercolor-edge-check/README.md) records the corrected check and its limits. Changing the checker wording does not invalidate an existing reference: a known faulty reference still needs an owner correction/remake before release.

Each JPEG is stored in Convex file storage through the `storeReferenceBlob` action and recorded with the exact inputs it was made from: the entry and stage text versions, the Classical style version and the era text for a sheet; the style version and main-era text for a style reference. `getReference` reports staleness against the current inputs, so a changed canon stage, style file or era remakes only its own references on the next run; a pinned reference is left alone until unpinned. Previous moment images are never used as references. The command is budgeted, resumable (`references.json` beside the reading state) and owner-funded; `--dry-run` lists what would be made.
