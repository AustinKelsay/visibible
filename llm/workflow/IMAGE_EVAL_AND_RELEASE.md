# Image eval and release requirements

Apply this process when changing the generic engine's prompt or preparation, an art style, the default image model, or anything else that can change what a verse's image looks like. It is the image half of [Spec S10](https://github.com/AustinKelsay/visibible/issues/54); the chat half is [Chat eval and release requirements](CHAT_EVAL_AND_RELEASE.md).

## The harness

`npm run evals:images` ([scripts/evals/images.mts](../../scripts/evals/images.mts) over [src/lib/image-evals](../../src/lib/image-evals)) runs the committed cases in [evals/images/cases.json](../../evals/images/cases.json) through the generic engine's own assembly and the same OpenRouter request the engine makes, one arm per art style ([below](#generic-engine-arms)). The legacy `direct` and `planner` arms were removed with the legacy engine ([#184](https://github.com/AustinKelsay/visibible/issues/184)); historical run states keep their planner fields. Every case has a reference, translation, settings and the visual behaviour a reviewer expects; the set covers narrative, poetry, prophecy, genealogy, symbolic and difficult passages and keeps the Peter, Red Sea and Genesis continuity cases.

- `--dry-run` writes a costed manifest and makes no call. `--budget` is a hard provider-spend limit checked before every paid call; the run stops at it and marks the remaining samples not run. Missing provider usage is recorded as such and charged to the budget at the per-call estimate, never as zero.
- `--repeats` (default 3) samples each case and arm repeatedly; a case is **inconclusive** when an arm has fewer than three completed samples and **incomplete** when the run stopped before every repeat. Both retain the baseline.
- Runs are resumable: `evals/images/runs/<run>/state.json` keeps every sample, and a rerun with the same `--run` never repeats a completed one. A different image model needs a new run name, and a historical run made with a planner cannot be resumed.
- An HTTP 402 from the image adapter stops the run with `stopped.reason: "provider_funding"`. The failed sample and any paid preparation work are saved together; later samples stay not run. Resolve the provider's funding requirement before explicitly resuming the same run. There is no automatic retry for a funding rejection; ordinary sample errors retain partial results and continue as before.
- Outputs are kept under `evals/images/runs/<run>/outputs/` and cited by stable path in `report.json`, `contact-sheet.html` (every sample of every case, failures included) and `scores.json`, the template a reviewer fills in. The runs directory is not committed.

## Generic engine arms

`--arms generic` (the default) runs one arm per art style (`generic:classical`, `generic:watercolor`, `generic:icon`, or the styles named with `--styles`), rendered through the request engine's own assembly ([engine/assemble.ts](../../src/lib/engine/assemble.ts)): the moment and its in-section neighbours from the imported text, the lazy section look and scene plan, the canon stages the plan marks present, the current reference sheets and style reference, and the validated rendering packet. A case may restrict its styles (`styles`), name a non-Bible work (`work`, `unitId`); the committed set carries three Holmes continuity cases beside the Bible ones.

- `--analysis convex` (the default when the deployment variables are set) reads the deployment's active analysis and references and must match this checkout's work and brief versions; `--analysis <run>` builds an in-memory analysis from `works/<id>/.preparation/<run>/{state.json,canon.json}` with no references, for rehearsals without a deployment.
- Looks and plans made during a run are **owner preparation spend**, recorded per sample apart from the image, charged to the budget (three calls, a look, a plan and its review, assumed per sample in the dry-run manifest), and reported with prepared (look and plan already present) and cold samples told apart, including their latency percentiles.
- Each generic sample keeps its exact prompt, the packet (every input version, the references actually attached with their versions, the trim flags) and the quote the route would have made; the report compares reported usage to the quote (mean and maximum variance, mean quoted and actual credits, whether the five-credit Lite target held) and shows a style matrix of which cases ran in which style.
- `--style-file <path>` runs an owner-authored style trial under its id (`--arms generic:<id>`) without adding it to the library; `--cases` with a new `--run` is the targeted check after a correction ([owner corrections](OWNER-CORRECTIONS.md)).
- `--omit-style-reference` is a generic evaluation control for isolating style-image conditioning without editing a style file. Assembly first selects and trims the normal packet, then removes only its selected style reference and caption. It renumbers remaining captions, preserves selected sheets and trim decisions, and quotes the actual attachments; it never backfills a freed slot. The setting appears in state, manifest, generic samples, packet flags, report and contact/comparison headers. A configured dry run or any attempted run cannot change it on resume; use a new run name. Historical states without the setting mean normal selection. Dry runs now save their run configuration as well as their manifest. Normal generation exposes no such option. Preflight both modes against fixed inputs, verify the normal arm actually attaches a style reference, and keep style wording unchanged for a reference-only contrast. The [retained-input audit](../releases/2026-10-21-reference-input-audit/README.md) explains the diagnosis; the [12-image comparison](../releases/2026-10-21-reference-comparison/README.md) retained failures in both modes and did not justify a production correction. The control removes the image and its caption together, so their individual effects are not isolated. Neither this flag nor a dry-run budget authorizes paid calls.
- `--compare baseline,candidate` renders both runs side by side per arm with each side's verdicts from its `scores.json`, flags every candidate fail or worsening for review, and marks inconclusive or incomplete candidate cases as retaining the baseline.

Generic arms are scored on five dimensions: relevance, character/location identity, section continuity, style and artifacts. An observed depiction-rule or prohibited-likeness violation is a release fail whatever the averages; a known Icon border is recorded as an accepted limitation, never hidden.

## Scoring and gates

Score each arm of each case 0–2 on the dimensions above, and record one verdict: `pass`, `accepted limitation` or `fail`, with notes. Review every failed or edge case by eye; averages never hide them. Compare candidate and baseline on the same cases, repeats and settings. Material regressions and failures need review; an inconclusive comparison retains the baseline.

The report carries completions, failures by stage, latency percentiles, image and preparation spend, missing-usage counts and reproducibility metadata (prompt version, models, repeats, sample floor). Attach `report.json`, the scored `scores.json` and the contact sheet to the release PR with the rollback plan and the first-24-hour owner, as the chat process requires.

Nothing here authorizes spend: a paid run is the owner's decision under the `--budget` it names, and the repository tests exercise the harness only with fake providers.

## Consistency

The launch bar also checks that images that should agree do ([ADR 0008](../../docs/adr/0008-consistency-in-the-launch-bar.md)). [evals/images/consistency.json](../../evals/images/consistency.json) names fixed groups. Character groups cover one canon entry across stories; setting groups cover neighbouring verses of one section. A launch matrix must render every verse they name.

- `npm run evals:consistency -- pairs --results <results.ndjson>[,…] --out <dir>` ([scripts/evals/consistency.mts](../../scripts/evals/consistency.mts) over [consistency.ts](../../src/lib/image-evals/consistency.ts)) reads launch-matrix results with the `snapshot.json` beside each. Within each group and style, it pairs the shown images. A character pair needs the entry selected in both plans and the same canon stage. It checks every image against its recorded SHA-256 and writes `pairs.json` for scorers, `key.json` for the operator and one side-by-side picture per pair. The key also lists any group verse with no result row. `--images-root` finds images kept in another checkout.
- Two independent scorers judge every pair `same`, `different` or `unclear` from [the instructions](../../evals/images/consistency-scoring.md), blind to the key. The operator settles disagreements in a third file with the same shape, covering only the disputed pairs.
- `npm run evals:consistency -- report --out <dir> --scores <a>,<b> --operator <file> --styles <released styles> --baseline <previous report.json>` writes `report.json` and prints rates by kind and style, with the gate on the pooled released styles. The gate fails closed on a group verse the run never attempted, unsettled disputes, too few judged pairs, too many unclear pairs, a rate under its floor, or a fall of more than 10 points from the baseline. A refused verse counts as attempted.

Keep the pairs, key, scorer files, operator file and report in the release record beside the per-image scores. The [baseline](../releases/2026-10-29-consistency-baseline/README.md) shows the layout. Pass the latest measurement's report as `--baseline`; it is now the [first full measurement](../releases/2026-10-29-consistency-verses/README.md), which also shows how to carry verdicts for pairs already judged. Nothing here calls a model or spends.
