# Owner corrections runbook

`npm run works:correct -- <work-id> <command>` ([correct.mts](../../scripts/works/correct.mts), over [corrections.ts](../../src/lib/engine/corrections.ts)) is how the owner inspects and corrects a work's analysis after the fact. Every command runs with the deployment's server secret from `.env.local`; nothing here is reachable from a browser. Saved images and accounting are never changed by any command.

| Command | What it does |
| --- | --- |
| `attention [--closed]` | Lists open (or closed) attention items with reason, source (`checker` or `reader`), record, count, latest activity, detail and the image URL for sheets and style references. Checker reasons: `sheet_failed`, `style_reference_failed`, `canon_note`, `canon_check`, `quote_check_failed`, `unmatched_owner_edit`. Reader reports (`reader_report`) are listed apart and are never closed by an input change. |
| `inspect <entryId>` | The entry's current version and payload, its version history across generations, the sheet per stage with its pin state and URL, records that are stale against it, and its open attention. |
| `add-cast --file <correction.json>` | Adds one missing canon entry and its stage assignment to one existing section atomically. Verifies source quotes locally and refuses changed work/generation/section inputs, existing identities or incomplete stages. Makes no model call and closes no attention items. Exact retries are harmless. |
| `edit-stage <entryId> <stageId> --text "…" [--expect <version>]` | Writes an owner version of the entry with that stage's text replaced. The command names the version it saw (`--expect`, defaulting to the current one at read time); a newer current version makes it refuse as stale, while a retry of the same edit is harmless. Closes the entry's checker items as "source corrected" and prints the sheets now stale. |
| `set-kind <entryId> character\|location\|object [--expect <version>]` | Writes an owner version of the entry with its kind corrected, such as a city filed as a character. Image prompts list places under the setting and the rest as cast, and sheets use the character, location or object template by kind. An object keeps one stage. Closes its checker items. The next image of any section that assigns it uses the corrected kind. Its unpinned sheets are skipped as stale until `redo-sheet` or a reference run remakes them. A pinned sheet stays in use and `redo-sheet` refuses it, so inspect and unpin it first. |
| `set-depiction <entryId> form\|effects\|symbol [--expect <version>]` | Writes an owner version of the entry with its depiction mode ([ADR 0010](../../docs/adr/0010-work-depiction-profiles.md)): `form` draws it from its canon; `effects` never draws it; `symbol` draws it only as its canon's non-human form. The last two need the work's wording for that mode in its depiction profile, so a work without it refuses them. Use `form` for an entry the reading pass wrongly marked without form, such as a city or a road. Closes its checker items. The next image of any section that assigns it uses the new mode. |
| `pin sheet\|style <recordId>`, `unpin …` | A pinned reference ignores staleness and cannot be replaced; unpinning restores the dependency check. |
| `redo-sheet <entryId:stageId>`, `redo-style <styleId>` | Remakes one reference through the normal check loop (owner-funded, three attempts); refuses a pinned one. Closes its checker items when it succeeds. |
| `redraft <entryId>` | Runs the canon step with `--redraft` and `--activate` for one entry; the store carries every owner version forward, so a redraft never overwrites an owner edit. |
| `dismiss <attentionId> [--disposition …]` | Closes one checker item with a disposition (`dismissed` by default). A reader report refuses anything but its four dispositions. |
| `reports [--closed]` | Reader image reports: count, latest activity, verse, the image's art style, engine and source translation as the library resolves them, the previous disposition when reopened, and the image URL. |
| `report <attentionId>` | One report in full: every message with its time, the lifecycle history, the last closure, and the saved image's provenance (work, moment, section, style and brief versions, canon stages and references, plus look and plan versions on images saved before the lean engine; unknown for legacy images). |
| `resolve <attentionId> --disposition "…" [--correction kind:recordId:version] [--check "…"]` | Closes a reader report with exactly one of `source corrected`, `isolated rendering error`, `accepted limitation` or `dismissed`. `source corrected` must link the input version that fixed it (which must exist in the analysis) and the targeted check you ran. A later report reopens the item with this closure kept in its history. |
| `wipe [--including-owner] [--confirm-production]` | Deletes the work's generated analysis: records, generations, reference records and blobs, and open checker items. Owner versions stay unless `--including-owner`, and the next activation carries them forward. The work becomes not ready. A deployment that looks like production needs `--confirm-production`; the mutation also requires the work id as confirmation. |

An input edit, redo or redraft never closes a reader report, regenerates the reported image or alters its provenance; the owner decides with `resolve` after checking the correction. Counts and warnings never change canon, references, styles or images by themselves.

Corrections invalidate only actual dependents: a changed canon stage makes that entry's sheets stale, and the next image of each section that assigns it reads the new canon; nothing is regenerated until the owner reruns a reference command. The analysis keeps every version, so the inputs behind a saved image stay inspectable after any correction ([Analysis storage](../context/ANALYSIS-STORAGE.md)).

## Adding a missing cast entry

Use `add-cast` after source review establishes a missing identity, rather than reusing an unrelated entry or hiding supported figures. Its JSON file contains `workVersion` (the imported file's SHA-256), `expectedGeneration`, `sectionId`, `expectedSectionVersion`, `entryId`, `stageId`, optional `named` (default false), and a complete `entry` payload (`kind: "entry"`, `name`, `entryKind`, optional `hasForm`, and `stages`). Every stage needs a unique ID, complete nonblank canon text up to 500 characters and supporting `{ unit, quote }` pairs. Character/location entries allow at most three stages, objects one. Groups use `entryKind: "character"` and describe a typical member.

The command checks every quote verbatim against the imported work and requires at least one quote for the assigned stage inside the current section. Appearance invented where the text is silent remains an owner illustrative choice; quote validity does not prove those choices or group identity. [Daniel's ministering assembly](../releases/2026-10-22-daniel-cast-correction/README.md) is a complete, source-checked example, retained as unapplied data.

The server verifies the owner secret, work version, active generation and expected section version before atomically inserting the owner entry and appending its section assignment. Existing cast members keep their stages. An existing entry ID refuses a conflicting addition; a retry whose exact entry and assignment already stand returns unchanged. No references are generated and no report is closed. A future full reread must retain the added entry's ID before carrying this owner section forward, or structural activation refuses the missing dependency.

## Targeted check after a correction

After editing a stage, redoing a sheet or pinning a reference, check the affected moments rather than the whole set. Either generate each verse that shows the entry or section in the app, or take a fresh snapshot (`npm run evals:lean -- snapshot --run snapshot-<date>`, free and read-only; a run sees only the canon and sheets of the snapshot it names), plan a narrow run from it with `--cases <the cases that show the entry or section>`, rehearse it offline, and run it once the owner funds it. Look at the images and close the reader report with `resolve … --disposition "source corrected" --correction <kind:recordId:version> --check "<what you generated and what you saw>"`. See [Image eval and release requirements](IMAGE_EVAL_AND_RELEASE.md).
